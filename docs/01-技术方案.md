> 2026-11-13 调研。结论先行：**排盘是纯数学，解读才用 LLM；历法和纳甲的轮子都有现成的，我们只造两层差异化：古籍 RAG + 产品体验。**

**所有高星项目的共同架构（本次调研最大收获）——三层铁律：**

1. **排盘引擎 = 纯确定性计算**。历法、干支、起卦、纳甲全部程序算，绝不靠 LLM 猜（多个项目原话："先把每一爻算清楚，再让大模型断盘"、"脚本先计算，方法论再解释"）。
2. **解读层 = 排盘结构化 JSON + 提示词模板 → LLM**。LLM 只负责"翻译"盘面为白话，不负责算。
3. **呈现层** = HTML 报告 / CLI / MCP / Web，风格统一（水墨/宣纸/朱砂印是行业标配视觉）。

**我们的差异化资产**：同类项目几乎全靠通用大模型裸答，**没有古籍语料**。高星项目 liki（103★）单靠"断语附经典出处，结论可验证"一个卖点就立住了——我们手里 10 本公版古籍正好是这个方向的弹药。

## 二、我们的设计

### 形态判断

**Web App（纯前端排盘 + 可选 LLM 解读）**。理由：零部署成本、手机电脑都能开、和 ai-diag/web-demo 同一套路已验证过（纯前端零依赖）。不做小程序（需要审核主体，娱乐项目不值得）、不做 CLI（没人天天用命令行算命）。

### 架构

```
┌─────────────────────────────────────────────┐
│  呈现层  Web 单页（水墨风：宣纸底/毛笔字/朱砂印） │
│  八字排盘页 · 六爻起卦页 · 每日运势页            │
├─────────────────────────────────────────────┤
│  排盘引擎（纯 JS，确定性，离线可跑）             │
│  ├─ 历法/四柱/神煞 ← lunar-javascript（现成）  │
│  └─ 六爻起卦/纳甲/六亲/世应 ← 自写（借鉴       │
│     fortune-liuyao 的京房八宫数据表）          │
├─────────────────────────────────────────────┤
│  解读层（两档，可独立工作）                     │
│  ├─ v1 规则引擎：调候表/卦辞爻辞/神煞断语       │
│  │   程序化映射 + 古籍原文摘录（无需任何 API）   │
│  └─ v2 LLM 解读：排盘 JSON + 古籍 RAG 片段     │
│      → DeepSeek API（key 就绪后接入）          │
├─────────────────────────────────────────────┤
│  语料层  books/ 10 本古籍（本地 RAG 源）        │
│  + ima 知识库（我对话时查证用，不进 App）        │
└─────────────────────────────────────────────┘
```

### 关键设计决策

1. **排盘绝不进 LLM**：四柱、纳甲、世应、五行旺衰全部本地算，LLM 只拿结构化结果做白话翻译。这保证可复现、可审计、离线也能出盘。
2. **解读引用带出处**：每条断语尽量挂古籍书名（如"《穷通宝鉴》：甲木生于申月，用丁"），这是同类项目没有的卖点。
3. **v1 不依赖任何 API key**：规则引擎 + 古籍摘录就能出一份完整报告，LLM 是增强不是依赖。
4. **古籍 RAG 用本地 books/**：App 内做关键词/分段检索原文片段喂给 LLM，不用 ima（ima 是我帮你查证用的，App 不依赖它，用户也不用登录）。
5. **娱乐免责**：页面显著位置标注"仅供娱乐，不宜迷信"。

### 功能清单（v1）

| 功能 | 排盘 | 解读 |
|---|---|---|
| 八字排盘 | lunar-javascript：四柱、五行分布、日主、大运 | 调候用神（穷通宝鉴表）+ 神煞断语 + 古籍摘录 |
| 六爻起卦 | 三次点按模拟摇钱（或手输硬币）→ 本卦变卦、纳甲、六亲、世应 | 卦辞爻辞（周易原文）+ 体用断法（梅花易数） |
| 每日运势 | 今日干支、宜忌、吉神方位（lunar 现成） | 简评 + 随机签文式短句 |

### 与本项目其他环节的关系

- ima 新知识库（等你手动建）：给我查证用，App 本身不依赖
- DeepSeek API：v2 接入，key 你提供后我加一个配置项即可
- 设计语言：水墨风独立设计，不套用 ai-diag 的 07 轨道风格
