## 一、一句话定义

**一个"看得懂、能追到原文"的命理小站**：你给生辰或问一件事，它排盘、落断语，每一句断语下面都压着古籍原文与出处。

对外一句话：**不问吉凶，先观其澜。**

---

## 二、为什么做

### 2.1 现有工具的三处失效

普通人打开市面上的排盘软件，会在三个地方卡住：

| 失效点 | 具体表现 | 后果 |
|---|---|---|
| **术语墙** | "身旺财弱，以食伤生财为用，忌比劫"——每个字都认识，合起来不懂 | 看完不知道跟自己有什么关系 |
| **无出处** | 结论直接给，不给理由 | 无法验证，只能信或不信 |
| **只给结论，不给行动** | "今年运势平平" | 用户真正想问的是"那我该不该换工作" |

多数产品把功夫花在"排得全"（神煞几十项、盘面花花绿绿），但**用户要的不是全，是"所以我该怎么办"**。

### 2.2 我们手里的牌

十种公版古籍全文（《周易》《梅花易数》《增删卜易》《卜筮正宗》《渊海子平》《三命通会》《子平真诠》《滴天髓》《穷通宝鉴》《千里命稿》），共 29779 条文本片段。

这决定了我们不做"又一个排盘工具"，而做**一个能引经据典的回答者**。同类开源项目几乎都是让通用大模型裸答，没人有语料库——这是唯一真实的差异点。

## 三、用户与场景

### 3.1 用户分层

| 层 | 描述 | 他要什么 | 我们的应对 |
|---|---|---|---|
| **A 好奇路人**（主要） | 完全不懂命理，被朋友发链接进来 | 30 秒内看到一个跟自己有关、能看懂的结论 | 三层断语；首页零输入即可看"今日流日" |
| **B 半懂爱好者** | 知道甲乙丙丁、听过用神，但不会断 | 想知道"我这盘为什么这么说" | 依据段 + 术语折叠解释 + 原文出处 |
| **C 入门学习者** | 在读古籍，想验证理解 | 原文检索、卦爻原文对照 | 藏书检索 + 彖/象/小象全量入库 |

**明确不服务**：要专业断事（择日、风水布局、合婚）、要"大师口吻"恐吓式断语、要付费撮合真人的需求。

### 3.2 典型场景

1. **深夜随手一问**：睡不着，想问"这份工作还要不要干下去"。不想注册、不想付钱、不想看广告。
2. **朋友聚会**：有人起哄"算一卦"，打开手机摇六次铜钱，三分钟出结果，能截屏发群。
3. **看不懂盘的人**：别人给他排了盘，一堆字看不懂，来这儿对照着看"人话版"。
4. **学古籍的人**：记得"甲木参天，脱胎要火"，想不起出自哪本，搜一下。

### 3.3 使用环境假设

手机为主（约 7:3），常在夜间；可能在地铁/电梯里断网；不愿意为一次好奇注册账号。

→ 直接推出三条产品约束：**零注册、纯前端、离线可用**。

## 四、产品原则（不可破）

这三条是判断一切设计争议的标准，写进代码注释也写进产品。

### 原则一：排盘是数学，不是猜测

四柱、节气、起卦结果、变卦，全部由确定性算法得出（lunar-javascript + 本地起卦逻辑）。**任何环节都不交给语言模型去估**。四柱错一个字，后面全部作废。

推论：LLM 接入后（v2），它只能读已经算好的盘，**不允许重算**。

### 原则二：断语必须可追溯

页面上出现的每一句"依据"，都要能指到具体书名。不能指到出处的说法，宁可不写。

推论：不做"看起来很深奥但没有出处"的发挥；不用"大师认为""普遍认为"这类模糊归因。

### 原则三：白话只解释原文，不发明原文

今译层的工作是**把原文里已有的意思讲清楚**，而不是补充原文没有的判断。

推论：今译引擎按"意象词 + 吉凶落点"抽取，而非整段自由改写；遇到原文没有的信息，就不说。

## 五、信息架构

五个视图，非菜单式导航。首页以水面构图承载入口，其余四页为内容页。

```
首页（观水）
├── 排命  bazi    生辰 → 四柱 / 五行 / 大运 / 三层断语
├── 问卦  liuyao  摇六次 → 本卦·变卦 / 卦辞·彖·象 / 变占断法 / 今译
├── 流日  today   当日干支 / 宜忌 / 十二时
└── 藏书  books   十种古籍全文检索
```

**为什么不做底部 Tab**：命理产品的价值在"一次完整的仪式"，而不是高频切换的功能集合。首页用一整面水 + 三滴水珠入口，把"选择"变成"投一滴墨"。

调试/分享可用 hash 直达：`#bazi` `#liuyao` `#today` `#books`。

## 六、功能规格

### 6.1 排命（八字）

**输入**

| 字段 | 类型 | 默认 | 校验 |
|---|---|---|---|
| 出生日期 | date | 1995-08-16 | 非法值静默回落到默认，不阻断 |
| 出生时辰 | 12 选项（子~亥） | 午时 | — |
| 性别 | 乾造 / 坤造 | 乾造 | 决定大运顺逆 |

**输出结构（自上而下）**

1. **四柱**：公历 + 农历 + 乾/坤造 + 起运时间；四列竖排，每列 = 天干 / 地支 / 十神 / 藏干 / 纳音
2. **一句话结论**：按旺衰四档取语料，楷体大字
3. **该干嘛**：三条行动建议（编号）
4. **五行**：五条权重条形图，月令加权
5. **大运**：九步，当前所行以朱色标出
6. **依据**：三段术语断语（月令关系 / 旺衰取用 / 五行偏枯）+ 3 条古籍引文
7. **术语折叠**：20 个词的通俗解释
8. **朱印「命」** 收尾

**核心算法口径（便于复核）**

- 五行权重：天干计 1；地支藏干本气 ×1.2、余气 ×0.42，月柱整体再 ×1.7（月令加重）；无藏干时按支本身五行 ×系数
- 旺衰判据：同党（日主五行 + 生我之五行）占比 `ratio`
  - `> 0.56` 偏旺 ｜ `> 0.46` 中和 ｜ `> 0.36` 偏弱 ｜ 其余 极弱
- 九步大运由 lunar-javascript 依性别与年干阴阳顺逆推出

**边界与空态**

- 日期不合法 → 用默认值跑，不弹错误框（headless 与真机的 alert 都会打断体验）
- 五行某项为 0 → 条形图不渲染该条，文案提示"一处几近于无，是全局缺口所在"

### 6.2 问卦（六爻）

**输入**：所问之事（自由文本，仅用于页面回显，不参与计算）

**流程**：点"摇卦" → 三枚铜钱翻飞 → 连续六次，自下而上成爻 → 出卦。

**爻的生成**：三枚钱，正面数 3 / 二 / 一 / 零
| 结果 | 名义 | 阴阳 | 动静 |
|---|---|---|---|
| 3 正 | 老阳 | 阳 | 动 |
| 2 正 1 反 | 少阴 | 阴 | 静 |
| 1 正 2 反 | 少阳 | 阳 | 静 |
| 0 正 | 老阴 | 阴 | 动 |

**判断规则：朱熹《周易本义》变占法**

| 动爻数 | 以何辞为断 |
|---|---|
| 0 | 本卦卦辞 |
| 1 | 本卦该动爻爻辞 |
| 2 | 两动爻爻辞并观，**上爻为主** |
| 3 | 本卦与变卦卦辞并观，**本卦为主** |
| 4 | 变卦中两不变爻，**下爻为主** |
| 5 | 变卦中唯一不变爻 |
| 6 | 乾 → 用九；坤 → 用六；其余 → 变卦卦辞 |

这是本产品最有价值的一段"硬知识"：它让"该看哪句话"有典可依，而不是随手挑一句。

**输出结构**

1. 本卦 / 变卦两列卦象（阳爻实线、阴爻断线、动爻标朱色 + ○/×）
2. 一句话结论 + 三条行动（64 卦各有专属语料）
3. 卦辞 → 彖 → 象（含变卦大象）三段原文
4. 断：主断爻辞 + 小象 + **今译**
5. 术语折叠（18 词）+ 朱印「卦」

**今译引擎（不是字典）**

- **意象词命中即解释**：49 条意象表（黄牛之革 / 涉大川 / 飞龙在天 / 桎梏…），取原文中最长者优先，避免"革"与"黄牛之革"重复命中
- **吉凶落点按权重**：元吉 > 吉 > 无咎 > 悔 > 吝 > 厉 > 凶（14 条判词）
- **一爻两说特殊处理**：如「征凶，居贞吉」不能笼统判凶，须分句输出"往外冲不吉，守住才吉"，并注「征＝往外冲、居＝守在原地」

**为什么不做 448 条硬译**：逐条手写易出错、体积大、维护难；引擎法只用原文既有信息，新增意象词即可覆盖新爻。

### 6.3 流日（今日）

**输出**：当日干支大字 → 公历/农历/年月日干支/节气 → 宜忌（各取前 10）→ 十二时辰格阵（冲为凶、合与同为吉）→ 2 条引文 → 朱印「日」。

**零输入**：打开即可看，是 A 类用户的第一触点。

**口径声明**：宜忌依《协纪辨方书》择日之法，仅取大意——页面上明写这句，不假装权威。

### 6.4 藏书（检索）

**输入**：一个词、一句原文、或一个卦名。

**检索策略**

1. 长句按 2 字切片（≤3 字直接作为关键词），去重
2. 逐行匹配，计命中比例：全中 +26，比例 ×30
3. 书目权重：滴天髓 1.16 / 穷通宝鉴 1.14 / 千里命稿 1.10 / 子平真诠 1.06 / 三命通会 1.04 / 周易 1.02 / 渊海子平 1.00 / 梅花易数 0.96 / 增删卜易 0.94 / 卜筮正宗 0.94
4. 取前 30 条，命中词高亮，标书名，显示条数与耗时

**空态**：十种书里未见此语 → 引导换说法（提示可试"身弱""用神""潜龙"）。

## 七、内容与数据体系

### 7.1 数据分层

| 层 | 内容 | 规模 | 来源 |
|---|---|---|---|
| 原文层 | 十种古籍全文 | 29779 条 / 3.2MB | 殆知阁 daizhigev20「易藏」（公版，简体纯文本） |
| 结构化层 | 64 卦：卦辞 + 448 爻辞 + 彖 + 大象 + 小象 | 78KB | 由原文解析（`build_data.py`） |
| 白话层 | 术语 43 条、卦解 64 条、旺衰 4 档、十神 10 条、五行 5 条、爻辞意象 49 条、判词 14 条、建议 8 条 | 16KB | 人工撰写，可编辑 |
| 历法层 | 干支/节气/宜忌/四柱/大运 | — | lunar-javascript（自托管） |

### 7.2 构建管线

```
books/*.md ──build_data.py──> site/data/gua.js（结构化）
                           └─> site/data/books.js（检索语料）
site/data/plain.js（人工维护，不入构建）
```

底本不规整，解析必须兜底。已处理的四类：

| 问题 | 处理 |
|---|---|
| 蒙卦卦辞与《彖》挤在同一行 | 段内拆分 |
| 大象不只用「君子以」（比用「先王以」、泰用「后以」、离用「大人以」） | 改为**按位置**判定：彖之后、爻之前 |
| 乾卦大象排在六爻之后且与小象同段 | 按「君子以」截句 + 引号切分 |
| 家人卦原文把六四误作「九四」 | 按顺序取爻辞，爻题由卦象决定 |

质量校验：64 卦彖与大象齐全；448 爻小象仅缺 2 条（底本本身缺失）。

### 7.3 内容创作规范

- 一句话结论：不超过 30 字，必须有判断，不用"可能""或许"
- 三条行动：动词开头，可执行，不涉生死/疾病/婚姻断言
- 白话用"你"不用"命主"；不用文言词替换（"泄秀"要写成"往外使力"）
- 引文原文一字不改，错字也不改（在文末注明底本情况）

## 八、视觉与交互

完整规范见 `02-UI设计大纲.md`，此处只列产品侧约束。

**视觉母题：水。** 整个首页是一整面水：游丝水纹三层（远/中/近，近大远小）、一滴墨落水、八重涟漪、碎月倒影。三个入口是三枚浮在水面的水滴。

**墨分五色**：焦 `#0F0D0B` / 浓 `#1C1A17` / 重 `#4A463F` / 淡 `#8C8577` / 清 `#C7C1B2`。底色为靛墨深水 `#050810`，全页唯一的暖色是朱砂印。

**动效基准 4.2s**：一滴墨的完整周期。涟漪八圈错峰 0.525s，形成"阵阵"而非一次性；所有转场以墨晕（模糊+淡入）实现，禁弹跳闪烁。

**交互隐喻**：每次操作都是"往水里投一滴墨"。六爻摇六次，正是六滴水相继入水——交互隐喻与业务动作同构，这是本产品体验上的关键一笔。

**迁移与降级**：三枚水滴入口 → 点选后从该点荡开涟漪化入功能页；移动端 ≤560px 单独调排版（水滴缩至 66px、标签字距归零）。

## 九、成功标准

不做虚荣指标（PV、停留时长），按"用户是否真的懂了"验收。

| 维度 | 验收方式 | 目标 |
|---|---|---|
| **看得懂** | 找 3 位完全不懂命理的人，看完结果页后口述"我该往哪走" | 3/3 能说出至少一条具体行动 |
| **可追溯** | 抽查任意结果页的"依据"段 | 每条引文都能在藏书中检索到同名原文 |
| **不出错** | 固定输入复现（如 1988-03-21 午时；初九老阳+上六老阴） | 四柱、卦象、动爻与手工核对一致 |
| **可信边界** | 出现无法从原文推出的判断 | 数量为 0；不确定时说不知道 |
| **可用** | 4G 首屏、断网二次访问 | 首屏 < 2s；离线可排盘（除字体） |

## 十、版本路线

### v1（已上线）

排命 / 问卦 / 流日 / 藏书四功能；规则引擎断语；三层结构；全量彖象小象入库。

### v1.1（下一步，不依赖外部服务）

- 白话覆盖补全：卦爻今译遇到意象词缺失时，目前退化为只给吉凶落点；补语料
- 大运逐步配一句话（现在只有干支与年份）
- 结果页"存为图片"，便于分享
- 术语词典按页面差异化裁剪（现在八字页 20 条偏多）

### v2（需外部能力）

**接大模型做追问**。约束条件：

- 只解释已算出的盘，**禁止重算四柱/纳甲**
- 引用必须来自本地语料，不许自由发挥
- 走免密钥云服务，前端不碰 key；需联网，2~5s 延迟可接受
- 作为"再白话一点""那我今年该不该换工作"的第二层，**不是首屏依赖**

### 明确不做

| 不做 | 原因 |
|---|---|
| 小程序 | 需主体审核，娱乐项目不值得 |
| 账号体系 / 用户数据存储 | 违背"零注册"约束；也算数据负债 |
| 付费断事、真人撮合 | 滑向迷信经营，触碰合规边界 |
| 纳甲六亲 / 世应用神 | 是另一套体系，做半套比不做更误导；宁可明确说"本产品走周易筮法" |
| 风水罗盘 / 择日 / 合婚 | 场景重、争议大，v1 不碰 |

## 十一、风险与合规

| 风险 | 处置 |
|---|---|
| **定性风险** | 全站口径为"传统文化研习与娱乐"，页脚固定免责声明；不用"预测""准确率"等词 |
| **误导风险** | 白话会让人更当真 → 措辞留余地；不碰生死、疾病、婚姻、投资断言 |
| **底本风险** | 古籍有传抄错字（如家人卦六四）→ 算法容错，文档公开说明 |
| **合规风险** | 不涉赌博、不涉迷信经营、不做付费断事；内容均为公版古籍 |
| **技术风险** | 浏览器无法直连知识库服务（需服务端鉴权）→ 改为把语料打包进前端，等价且可离线 |

## 十二、开放问题

1. **专业度与通俗度的平衡点在哪**？现在偏通俗（三层断语先行、术语折叠）。若面向 B/C 类用户，是否需要"专业模式"开关？
2. **六爻要不要补纳甲**？补了贴近实战派，但会与现有卦辞体系并行，可能造成"两套说法打架"。
3. **LLM 追问的边界怎么写进提示词**？需要一份"禁止重算 + 必须引用 + 不确定要说不知道"的硬约束模板。
4. **是否要做分享图**？做了能带来传播，但也会让断语脱离出处语境（截图只留结论，不留原文），与产品原则二有张力。

## 附录 A：术语口径
