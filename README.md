# 观水 · 断易

> 水无常形，命无常势。必观其澜，不观其花。

一个水墨风格的命理 web 应用：**八字排盘、六爻问卦、今日流日、古籍检索**。
纯前端、零后端、不依赖任何 API Key，双击就能跑，也能直接丢到任何静态托管上分享。

**[在线体验](https://wbapp-8yu7pyqibqhbovtm6r7dpx.app.workbuddy.host/?sharecode=64DS7JODD2)**

## 两条不能破的原则

**一、排盘是数学，不是猜测。**
四柱、节气这些全部是确定性计算，由 [lunar-javascript](https://github.com/6tail/lunar-javascript) 承担（已自托管在 `site/vendor/`）。任何环节都不交给语言模型去「估」——四柱猜错一个字，后面全错。

**二、每句断语都要能追到原文。**
断语不当空口结论，每段下面都挂着古籍引文与出处。这不是装饰：用户问「凭什么」，页面能立刻答。

围绕第二条，结果页做成三层结构：

1. **所以呢** —— 一句人话结论
2. **该干嘛** —— 三条可执行的行动
3. **凭什么** —— 术语依据 + 古籍原文 + 今译

<p align="center"><img src="docs/preview/mobile.jpg" width="300" alt="手机端"></p>

爻辞的「今译」是引擎而非字典：从原文里抽意象词（如「黄牛之革」→ 老黄牛皮最韧，捆东西最牢）、按权重判吉凶落点，并特殊处理「征凶，居贞吉」这类一爻两说的句子（往外冲才凶，守住是吉）。全程只用原文里已有的信息，不改写、不编造。

## 快速开始

```bash
git clone https://github.com/wenyuhang666/guanshui.git
cd guanshui
```

三个文件即可运行，**不需要 npm install，不需要后端**：

- 直接双击 `site/index.html`
- 或起个静态服务：`cd site && python -m http.server 8000` → 打开 http://127.0.0.1:8000

调试用的 hash 路由：`index.html#bazi`、`#liuyao`、`#today`、`#books`。

## 数据是怎么来的

原始文本取自 GitHub 上的公版古籍库 [殆知阁 daizhigev20](https://github.com/garychowcmu/daizhigev20)「易藏」，全部为简体纯文本，无需 OCR。

```bash
python build_data.py     # 改书单或换底本后重跑
```

脚本从《周易》原文里解析出 64 卦的卦辞、六爻爻辞、《彖》《象》（大象）与《小象》。底本的排版并不规整，构建时逐条兜住了：

- 蒙卦的卦辞与《彖》挤在同一行，需按段内拆分
- 大象判据不能用「君子以」——比卦用「先王以」、泰卦用「后以」、离卦用「大人以」，故改为按位置判定（彖之后、爻之前）
- 乾卦的大象排在六爻之后且与小象同段，按「君子以」截句 + 引号切分还原
- 家人卦原文把六四误作「九四」，改为按顺序取爻辞、爻题由卦象决定，底本有错也不致算错

校验结果：64 卦彖与大象齐全，448 爻小象仅缺 2 条（底本本身缺失）。

## 已知局限

- 六爻走的是《周易》筮法（朱熹《周易本义》变占法），**没有**做纳甲、六亲、世应、用神——那是另一套体系
- 断语是规则引擎，覆盖四档旺衰与十神关系，长尾盘面仍会偏模板
- 尚未接入大模型。若接，约束必须是「只解释已算出的盘，不许自行重算」
